# 一炎自媒体与内容系统

内容系统的任务是持续让合适的人发现问题、理解方法、形成记忆、采取下一步，并把反馈沉淀为新的内容和产品证据。单条爆款不是系统，稳定发布也不自动等于有效。

## 先确认内容要完成什么

一次内容只设置一个主要任务：

- 被目标对象发现；
- 让用户意识到一个问题；
- 解释一个判断或方法；
- 提供可以保存和使用的工具；
- 用案例建立证据；
- 引导主页、私信、预约或购买；
- 服务已有学员和客户；
- 测试一个需求假设。

任务不同，形式、指标和 CTA 都不同。

## 核心流程

### 1. 建立受众情境

写清对象此刻发生什么、已经试过什么、注意力为什么会停下、看完想推进什么。人口标签不能替代情境。

### 2. 形成内容承诺

用一句话写：持续帮助哪类人看清哪些问题，主要使用什么判断方式，明确不提供什么。承诺必须小于等于专业能力和交付。

### 3. 设计内容组合

长期内容至少覆盖：

1. **问题与认知**：命名问题，建立相关性；
2. **观点与解释**：说明为什么；
3. **方法与工具**：展示怎样判断和行动；
4. **案例与复盘**：提供过程证据和反例；
5. **工作台与人格**：展示标准、取舍和边界；
6. **产品与邀请**：说明适配、交付和下一步。

内容战略、信息加工和说服边界见 [受众与信息设计](references/audience-and-message.md)。

### 4. 建立母题和选题

从客户问题、交付记录、反复误区、失败、方法步骤、行业变化和个人经历提取母题。每个选题写“对象—场景—冲突—主张—证据—动作”，避免只从热点和抽象关键词开始。

### 5. 选择形式

根据任务选择短视频、图文、长文、直播、播客、课件配音、屏幕录制或桌面手部。形式适配见 [形式与生产系统](references/formats-and-production.md)。不露脸可以成为稳定镜头语言，但不能代替观点和证据。

### 6. 写最小内容单元

发布前必须回答：

- 这一条只说什么；
- 哪个事实、案例、演示或来源支撑；
- 哪个限制必须同时说；
- 看完只希望用户做什么；
- 如何回收评论、私信、搜索或行为反馈。

### 7. 发布与复用

把一次研究拆成短视频、图文、直播段落、FAQ 和课程素材；保留原始事实、来源和版本，避免每次从零创作。

### 8. 按漏斗复盘

区分触达、注意、理解、信任、行动、成交、履约和长期价值。数据解释与实验见 [测量与实验](references/measurement-and-experiments.md)。

## 一炎表达结构

默认使用：

`具体冲突 → 场景 → 主张 → 判断过程 → 例子／证据 → 唯一邀请`

涉及象征、玄学或宗教时，可以使用“一炎四步转译”：

`象征／观点 → 现实事实 → 可执行动作 → 复盘证据`

必须标清象征与现实证据的边界。

## 默认输出

1. 内容任务和目标对象；
2. 内容承诺与母题；
3. 栏目组合；
4. 选题或脚本；
5. 证据与风险检查；
6. 发布、复用和反馈路径；
7. 对应指标与下一轮实验。

## 边界

- 不承诺爆款、涨粉、限流解除或平台推荐；
- 不把单个平台经验写成永恒算法；
- 不伪造收入、案例、身份、资质、评论或第三方背书；
- 不用恐惧、羞辱、诅咒、神秘权威和虚假稀缺换点击或成交；
- 医疗、心理、法律、投资、宗教与平台规则必须标明边界并核对当前可靠来源；
- 产品和成交问题分别进入 `$yiyan-product-design` 与 `$yiyan-brand-sales`。

理论与材料来源见 [来源与证据地图](references/source-map.md)。
